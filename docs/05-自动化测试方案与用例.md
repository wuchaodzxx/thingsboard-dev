## 1. 测试范围与环境

覆盖需求第五章全部 9 类：设备注册和认证、X.509 双向 TLS 成功及失败、上下线及异常重连、
数据上报及历史补传、属性下发及查询、召测与远程控制、指令执行状态闭环、异常报文及通信异常、
多设备并发接入及基础性能。

**判定原则**：全部基于真实交互取证——真实 TLS 握手（ssl 直连 18885）、真实 MQTT 链路、
TB REST 存储回读（遥测/属性/凭据/active）、模拟器指令台账双端对照；不以日志或模拟结果替代。
TB 遥测异步落库，断言一律轮询；two-way RPC 存在 active 竞态（409）由重试兜底。

**运行环境**：ThingsBoard CE 3.5.1（Docker：REST 18080 / MQTT over TLS 18885，X.509 双向认证）
+ 设备模拟器（FastAPI :19000，每台设备独立证书与独立 MQTT 连接）
+ 证书管理工具 certadmin（FastAPI :19001，独立容器 `vpp-certadmin`，v1.3 起负责证书签发/查看/导出）。
硬件条件由 conftest 在每轮自动采集（主机/OS/CPU/内存/Python/TB 版本）并写入结果 JSON 与 HTML 报告。

**TB 3.5.1 平台行为差异（用例设计依据，源码/字节码核实）**：
- MQTT TLS 层为 WANT 客户端认证（`MqttSslHandlerProvider` 硬编码 `setNeedClientAuth(false)`，
  无配置项）：无证书/伪造 CA 证书握手均可建立，设备认证与证书信任在 MQTT CONNECT 层强制
  （按证书指纹检索凭据，未注册指纹返回 CONNACK rc≠0）；TC-C2-02/03 以"能否完成接入"为
  判定标准而非握手层拒绝；
- 设备凭据 `credentialsValue` 以 **base64(DER)** 存储（TC-C1-02 与签发证书解码后逐字节比对）；
- 设备 `active` 非事件驱动：由 `DefaultDeviceStateService` 按 inactivity 超时（默认 600s）每
  60s 周期判定；支持设备级 SERVER_SCOPE 属性 `inactivityTimeout`（毫秒）覆盖且更新即时生效
  （TC-C3-01 置 30000ms，断开后 30~90s 内翻转 false）。

## 2. 参数化与运行方法

**v1.3 用例集（P7，当前版本验收）**——前置：certadmin :19001、模拟器 :19000、TB :18080/:18885 全部运行中
（certadmin 数据目录 `certadmin/data/` 宿主机可读（容器内挂载为 /data/secrets）；TB 侧已按 docs/03 §4.2 装配 certadmin 签发的服务器证书）：

```bash
# 全量 21 例（证书管理工具 14 + 模拟器回归 4 + 全流程 3）
.venv/bin/python -m pytest tests/p7_v13 -v

# 分组运行
.venv/bin/python -m pytest tests/p7_v13/test_c11_certadmin.py -v   # 证书管理工具 API
.venv/bin/python -m pytest tests/p7_v13/test_c12_sim.py -v         # 模拟器 v1.3 回归
.venv/bin/python -m pytest tests/p7_v13/test_c13_flow.py -v        # 线下同步全流程闭环
```

P7 用例数据统一 `tc7-` 前缀，每用例结束（含失败兜底）自动四级清理：
certadmin 登记簿与产物文件 → 模拟器设备与证书 → TB 设备；根 CA/中间 CA/服务器证书/交付样例
（dev-ca-01）等环境数据不受影响。单用例超时 600s（`tests/p7_v13/pytest.ini`）。

**v1.2 存档用例集（P6，仅回溯 v1.2 版本时使用）**：

```bash
# S=1 全量轮（功能 25 例 + 规模 5 例）
.venv/bin/python -m pytest tests/p6 --scale 1 -v

# S=10 / S=100 规模轮（仅并发用例）
.venv/bin/python -m pytest tests/p6 --scale 10 -m scale -v
.venv/bin/python -m pytest tests/p6 --scale 100 -m scale -v

# 汇总 HTML 报告
python tests/p6/make_report.py
```

- `--scale N`：并发规模设备数（命名 `p6s{N}-001…`），需求要求至少支持 1/10/100；
- 规模设备在用例组结束（含中途失败兜底夹具）后自动清理（模拟器 + TB 双侧删除）；
- 单用例超时 900s（`tests/p6/pytest.ini`），防止长等待用例挂死；
- 记录项（需求 5 章）：硬件条件、测试持续时间、成功率、响应时间（RTT 分布 min/avg/p95/max）。
