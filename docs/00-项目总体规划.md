# 虚拟电厂物联接入验证项目 — 项目总体规划

> 文档版本：v1.0（2026-11-03）
> 依据：《虚拟电厂物联接入验证项目补充技术要求》（需求文档.md）
> 状态：规划基线（随阶段推进更新）

## 1. 项目目标

基于 ThingsBoard Community Edition 3.5.1 构建虚拟电厂（VPP）物联接入验证环境，交付：

1. 完整可运行的源代码与部署编排（Linux / Windows 双环境）；
2. 设备模拟器（多设备、故障注入、证书管理 UI、日志页）；
3. 平台侧验证能力（注册/遥测/属性/召测/控制闭环/数据比对）；
4. 自动化测试（机器可读结果 + HTML 报告，1/10/100 设备）；
5. 《虚拟电厂物联设备通信与接入技术规范》。

## 2. 技术选型与固定版本

| 组件 | 选型 | 版本/镜像（固定） |
|---|---|---|
| 物联平台 | ThingsBoard CE | `thingsboard/tb-postgres:3.5.1`（固定 tag，升级需重新确认） |
| 数据库 | PostgreSQL | `postgres:14`（TB 3.5.1 官方配套） |
| 通信协议 | MQTT 3.1.1 over TLS 1.2+，X.509 双向认证 | 端口对外 18883（映射容器 8883） |
| 报文格式 | JSON（UTF-8） | 本规范定义 |
| 模拟器后端 | Python 3.11 + FastAPI + paho-mqtt 1.6.1 | 源码交付 |
| 模拟器前端 | Vue 3 + Vite + Element Plus（构建产物由后端静态托管） | 源码交付 |
| 自动化测试 | pytest + paho-mqtt + requests + jsonschema（ajv 语义） | 源码交付 |
| 证书 | OpenSSL（root CA / 中间 CA / 服务器 / 设备证书） | certmgr 程序封装 |
| 编排 | Docker Compose v2，环境变量配置，健康检查、持久化、初始化 | `deploy/docker-compose.yml` |

## 6. 关键设计决策（详见 01 规范）

1. **全部使用 TB 原生 MQTT Topic**（telemetry / attributes / rpc / claim），业务字段自定义封装；不定义 TB 无法识别的 Topic。
2. **业务心跳 = 遥测消息**（`{ts, values:{msgType:"hb",...}}`），与 MQTT KeepAlive（协议层）区分；设备真上下线以 TB 会话事件为准。
3. **控制指令闭环**：REST two-way RPC 下发（method=cmdType）→ 设备 RPC response 回 `ACK/REJECTED`（≤5s）→ 异步终态经遥测 `cmdStatus` 上报（SUCCESS/FAILED）→ 平台按 `expireAt` 判 `TIMEOUT`；`cmdId` 为幂等键。
4. **周期数据**：1 分钟（功率/电气量均值）与 15 分钟（含电量表码与区间增量）双口径；累计表码回绕、换表清零、首周期无基线等规则显式定义；数据质量标识 dqf。
5. **断点补传**：设备本地缓存 ≥24h，重连后按原生遥测数组格式批量补传（≤100 条/包），带原始时间戳。
6. **离线投递策略**：3.5.1 CE lightweight RPC 对离线设备不投递，规范明确"设备在线方可下发"，指令台账由平台侧维护，不依赖 PE 特性。
7. **证书**：默认逐设备 X.509 凭据（TB 3.5.1 确定支持）；证书链策略作为可选优化；根 CA 私钥仅存本地 secrets 目录，不入代码仓库。
